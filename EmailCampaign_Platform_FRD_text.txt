1 What Are We Building? 
 
You are building an Email Campaign Platform — a web app that lets teams create, send, and track email campaigns 
to large groups of people. 
Think of it like building your own version of Mailchimp or Zoho Campaigns, powered by AWS SES (Amazon's email 
sending service). 
 
What the app does — in plain English: 
• Manage contacts — store email lists, import from CSV, group people into lists. 
• Drag-and-drop email builder — design beautiful emails visually, no coding needed. 
• Create & send campaigns — send emails to hundreds or thousands at once. 
• Schedule sends — set a future date & time and the app sends automatically. 
• Track opens & clicks — see who opened your email and what they clicked. 
• Handle bounces & complaints — auto-remove bad email addresses. 
• Manage unsubscribes — people can opt out, the app respects that always. 
• Show analytics — dashboards with open rates, click rates, and more. 
 
 
■■ The Tech Stack (Recommended) 
 
Frontend: Any AI website builder — Lovable, Cursor, Bolt, v0, Builder.io, Webflow AI, etc. Backend: Node.js (Express) or 
Python (FastAPI / Flask) Database: PostgreSQL Email: AWS SES (Simple Email Service) Storage: AWS S3 (for images 
used in emails) Queue: AWS SQS (for sending at scale without crashing) 
■ Which AI Tool Should I Use? 
 
You can use ANY AI-powered web development tool. Popular options: • Lovable (lovable.dev) — describe your UI in plain 
English, get React code. • Cursor (cursor.sh) — Antigravity with AI that writes and edits your code. • Bolt (bolt.new) — 
full-stack app builder in the browser, no setup. • v0 by Vercel (v0.dev) — generate React components from a description. • 
Builder.io — drag-and-drop + AI for visual web building. Pick whichever you're most comfortable with. The goal is to ship 
fast!

M1 — Login & User Management 
 
 
What the Admin sees: 
• A login page with email and password fields. 
• After login, they land on the Dashboard. 
• Profile page to update name, email, and password. 
• Settings  Users page to invite teammates and assign roles. 
 
What the system does behind the scenes: 
• Stores passwords hashed (bcrypt) — never plain text. 
• Issues a JWT token on login; expires after 15 min, auto-renews silently. 
• Locks an IP for 15 min after 5 failed login attempts. 
• Shows/hides menu items based on the user's role. 
 
 
M2 — Contact List Management 
 
This is the address book of your app. All contacts and their groups live here. 
 
What the Admin sees: 
• Contacts sidebar with two sub-pages: Lists and Segments. 
• Lists page: grid of mailing lists — name, contact count, create/rename/delete actions. 
• List detail: table of contacts in that list — searchable, sortable, with bulk actions. 
• Contact detail: one person's info + which lists they're in + full email event history. 
• Import page: upload CSV  map columns  preview  import. 
• Segments page: build smart filters like 'opened last email but never clicked'.

M5 — Scheduling & Sending

• A background worker reads from the queue and calls AWS SES for each contact. 
• Must respect AWS SES rate limits — don't send too fast or SES throttles you. 
 
Scheduled Send: 
• User picks a future date, time, and timezone.

M6 — Open & Click Tracking 
 
 
How Open Tracking works — step by step: 
• When sending an email, the app adds an invisible 1×1 pixel image at the bottom. 
• The image URL points to your backend: /track/open?uid=ABC123 
• When the email client loads the image, your server records an 'opened' event. 
• The uid is a unique code that identifies the contact + campaign combination. 
 
How Click Tracking works: 
• Every link in the email is rewritten to pass through your server first. 
• Original: https://example.com/offer 
• Rewritten: /track/click?uid=ABC123&url=https://example.com/offer 
• Your server records the click, then instantly redirects to the original URL (HTTP 302). 
 
What to record for each event: 
• Which contact (contact_id), which campaign (campaign_id), when (timestamp). 
• For clicks: which specific link was clicked (original URL). 
• Device info: IP address and browser/email client (from User-Agent header). 
 
 
M7 — Bounce & Complaint Handling 
 
 
 
Types of email problems & how to handle them: 
■■ AWS SES Sending Limits — Read This! 
 
New SES accounts start in sandbox mode — you can only send to verified email addresses, with a 200 email/day limit. For 
the demo, this is fine — just verify a few test addresses. For production: request a sending limit increase via AWS Console 
 SES  Account Dashboard  Request Production Access. 
■ Use AWS SES Native Tracking 
 
AWS SES Configuration Sets can automatically track opens and clicks for you — no custom pixel needed. Set up a 
Configuration Set in SES, point events to an SNS topic, and your backend receives all events via webhook. This is the 
recommended approach. 
■■ AWS SES Rule — This is Non-Negotiable 
 
AWS requires: • Bounce rate must stay below 2%. • Complaint rate must stay below 0.1%. If you exceed these thresholds, 
AWS will pause your sending account. Your app MUST automatically stop sending to bounced and complained addresses.

How your app receives these notifications:

• Admin can manually add or remove entries (with reason logged in audit trail). 
• CSV import automatically skips any email found in the suppression list. 
 
 
M8 — Unsubscribe Management 
 
People must be able to opt out easily. This is both a legal requirement and best practice. 
 
Every email must include an unsubscribe link: 
• Added automatically in the email footer — the admin doesn't need to remember. 
• Link URL: /unsubscribe?uid=ABC123 (uid identifies the contact + campaign). 
• Clicking the link instantly marks the contact as unsubscribed. 
 
Unsubscribe confirmation page (public — no login needed): 
• Shows a friendly message: 'You have been unsubscribed from [List Name].' 
• Option to re-subscribe if they changed their mind. 
• Branded with the organisation's name and logo. 
 
One-Click Unsubscribe — required by Gmail & Yahoo (2024+): 
• Every email must include: List-Unsubscribe and List-Unsubscribe-Post headers. 
• Your backend handles a POST request to the unsubscribe URL immediately. 
• This lets Gmail/Apple Mail show a built-in 'Unsubscribe' button at the top of the email. 
• ■ Bonus: Preference Centre — instead of a full unsubscribe, let people pick which lists to stay on.

8 AWS SES Setup — Step by Step 
 
AWS SES is the engine that actually sends the emails. Here's how to set it up from scratch — even if you've never 
used AWS before. 
 
Step 1 — Create an AWS account 
• Go to aws.amazon.com  sign up or log in. 
• Search for SES (Simple Email Service) in the top search bar. 
 
Step 2 — Verify your email or domain 
• SES  Verified Identities  Create Identity. 
• For the (easiest): verify a single email address. AWS sends a confirmation email — click the link. 
• For production: verify your domain and set up DKIM (SES guides you through each step). 
 
Step 3 — Create a Configuration Set 
• SES  Configuration Sets  Create  name it email-platform-events. 
• Add an event destination: choose SNS topic. 
• Select all event types: Send, Delivery, Open, Click, Bounce, Complaint. 
 
Step 4 — Connect SNS  SQS (for bounce/complaint processing) 
• AWS SNS  Create a new topic. 
• AWS SQS  Create a new queue  Subscribe it to your SNS topic. 
• Your backend worker reads from this SQS queue to handle bounces and complaints. 
 
Step 5 — Request production access 
• By default SES is in 'sandbox' — you can only send to verified addresses (fine for hackathon). 
• For real users: SES  Account Dashboard  Request Production Access. 
 
Step 6 — Install the AWS SDK in your backend 
 
Language Install Command 
Node.js npm install @aws-sdk/client-ses @aws-sdk/client-s3 @aws-sdk/client-sqs 
Python pip install boto3 
 
■■ Never Hardcode AWS Keys in Your Code 
 
Store credentials as environment variables: AWS_ACCESS_KEY_ID=your_key 
AWS_SECRET_ACCESS_KEY=your_secret AWS_REGION=ap-south-1 Use a .env file locally and set environment 
variables on your hosting platform (Render, Railway, Vercel, etc.). Never commit your .env file to GitHub — add it to 
.gitignore!
